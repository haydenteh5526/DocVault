## Task 1: One soft focus border on the Ask composer

**Cause:**
- `frontend/src/index.css` draws a 2 px `--foreground` outline on every focused field. The rule near line 116 is unlayered, so it beats Tailwind's `focus:outline-none` on the textarea. In dark mode, `--foreground` is near-white.
- The wrapper at `AskAI.tsx:290` adds `group-focus-within:ring-2 group-focus-within:ring-ring` as well.
- The two together read as a thick white double border.

**Change:**
- `index.css`: both global focus rules (the one inside `@layer base` near line 98 and the unlayered one near line 116) skip elements marked as drawing their focus on a container:

  ```css
  :where(a, button, input, select, textarea, summary, [tabindex]):not([data-focus-ring="container"]):focus-visible { … unchanged … }
  ```

  The base-layer rule `:focus-visible` becomes `:focus-visible:not([data-focus-ring="container"])`.
- `AskAI.tsx`:
  - the textarea gets `data-focus-ring="container"` and keeps `focus:outline-none`
  - on the wrapper, `group-focus-within:ring-2 group-focus-within:ring-ring` becomes `focus-within:border-muted-foreground`, keeping `border border-border` and changing `transition-shadow` to `transition-colors`

  When the field has focus, the composer's 1 px border changes from `--border` to `--muted-foreground`. There is no outline or ring.
- Nothing else uses `data-focus-ring`.

- [ ] **Tests first:**
  - **`AskAI.test.tsx`:**
    - the textarea has `data-focus-ring="container"`
    - its wrapper's class list contains `focus-within:border-muted-foreground` and no `ring-2`
  - **`e2e/accessibility.spec.ts`**, new scenario "the Ask composer shows one soft focus border", in both light and dark schemes:
    - tab to the Ask textarea
    - its computed `outline-style` is `none`
    - the wrapper's computed `border-top-color` differs from its unfocused value
    - the wrapper's `box-shadow` is `none`
    - tab on to the send button, and its outline is still 2 px solid, so other focus outlines are untouched
- [ ] Gates. Commit: `Draw one soft focus border on the Ask chat box`

## Task 3: The service worker fetches pages from the network first

- `frontend/public/sw.js`:
  - `CACHE_NAME` becomes `'docvault-v3'`, so `activate` deletes the old cache that holds stale copies of `/` and `index.html`.
  - In `fetch`, a request with `request.mode === 'navigate'`, or a URL path of `/` or `/index.html`, goes to the network first. A successful response is copied into the cache. If the network fails, the cached copy is served, and offline loading still works.
  - Every other GET keeps today's cache-first behaviour. `/api/` requests are still never cached.
- [ ] **Test first** (`frontend/src/sw.test.ts`, new): evaluate `public/sw.js` with a stub `self` (capturing the listeners), `caches` and `fetch`.
  - A navigate request calls `fetch` before `caches.match`, and stores the response.
  - When `fetch` rejects, it returns the cached response.
  - A non-navigation static request with a cached copy is served from the cache without `fetch`.
  - An `/api/` request isn't intercepted.
  - `activate` deletes `docvault-v2`.
- [ ] Gates. Commit: `Fetch pages from the network first in the service worker`
