# Repository current state

**Snapshot, 12 November 2026.** The assessed checkout is DocVault. [PR #7](https://github.com/haydenteh5526/DocVault/pull/7) records the Demo 1 increment. The earlier prototype's development history is in [DocVault-old](https://github.com/haydenteh5526/DocVault-old).

## Demo 1 capability

Register or reset a disposable account with the local Mailpit inbox. Upload the [synthetic electricity bill](../evaluation/demo-1/synthetic-electricity-bill.pdf), wait for local OCR, and open **Summary → Bill review**. Compare the **€123.47** amount due, **23 November 2026** due date and **1–31 October 2026** billing period with their exact transcript lines and the original PDF. The rehearsal recorded an identical byte-for-byte preview. [Demo script and raw checks](../evaluation/demo-1/README.md)

The bill review screen displays read-only candidates. With [PR #13](https://github.com/haydenteh5526/DocVault/pull/13), the owner can correct the amount, due date and billing period, compare them with the OCR candidates and explicitly confirm them. Each confirmation appends a revision with integer cents and a snapshot of the reviewed evidence, and the confirmed values and evidence reopen even when the transcript no longer produces candidates. A save is rejected with nothing written if the evidence or revision changed while the owner was reviewing.

Since [PR #16](https://github.com/haydenteh5526/DocVault/pull/16) merged on 12 November 2026 as `d21d018`, the owner can save housemate names in their account and split the confirmed amount equally among 2 to 12 of them in whole cents. Four housemates is the acceptance case: €123.47 gives €30.87, €30.87, €30.87 and €30.86. The panel shows the rule, the order and the total, and the owner reviews the exact shares before saving. A save is bound to the confirmed revision, the latest split number and the reviewed shares, and is refused with nothing written if any changed. A saved split is never recalculated: confirming a newer revision marks it out of date. Cached data is dropped when the account changes, and the service worker no longer stores API responses. The manual check with the synthetic PDF passed on `1cc935b` on 12 November (see the verified results). [Issue #2](https://github.com/haydenteh5526/DocVault/issues/2) stays open for the maintainer to close. On the branch `feature/issue-3-reminder-approval` (issue #3, not yet merged), the owner can propose a reminder a number of days before the confirmed due date, see the exact bill, amount, reminder date and any current split, and approve or cancel it. The server builds the details from its own records and stores them as a pending proposal. Approval is bound to the details the owner reviewed and to the bill revision and split the proposal was made from, checked under the document row lock. The first approval saves one reminder (201), a repeat returns the same outcome (200), and a bill or split that changed leaves the proposal marked out of date with nothing saved. Every step is recorded in a history of what was proposed, approved and saved. Limits: a saved reminder is shown only in the document's Reminder panel, nothing is delivered (no push, email, calendar file or payment), and a reminder date that has already passed is allowed and labelled. Natural-language tool selection is the next increment. [Design](MVP_Technical_Design.md) · [Tickets](Tickets.md)

## Runtime

The web client uses React and Vite. FastAPI manages account and document access. The Docker stack uses PostgreSQL with pgvector, Redis and ARQ, RustFS as the S3-compatible store for private files, Tesseract for local OCR, Ollama for local embeddings and Mailpit for local account email. Expo is a companion client. See the [README](../README.md#quick-start) for setup, the [technical design](MVP_Technical_Design.md#architecture-and-evidence-flow) for the evidence flow and [verification guide](../AGENTS.md#verification) for test commands.

The assessed demo uses the existing hardware and local stack with **€0 planned additional spend**. Local Compose and browser CI both use `rustfs/rustfs:1.0.4` as the S3-compatible store. It replaced MinIO after the CI runner could not pull `minio/minio:latest` on 9 November. The 7 November rehearsal used the earlier MinIO image. Files in an existing local `miniodata` volume are not carried over.

## Remaining evidence and limits

- Offline reads of API data no longer work: the service worker stopped storing API responses so one account's data cannot be served to another on the same browser. Static assets are still cached.
- Saved housemate labels are names only, not linked to user accounts. They can be added and removed but not renamed. The save is checked on the server. The two-tab conflict was checked once by hand in two real browser tabs, not by an automated test.

- The synthetic examples establish the demo behaviour. Field accuracy on varied bills, cross-owner access for new records and safe approval retries still need evaluation. Local model task selection was measured for `qwen3:8b` only and did not meet the threshold. Other local models are untested, and no local model is integrated. [Evaluation workspace](../evaluation/README.md)
- The mobile check covers types and Expo configuration. The lockfile update to `shell-quote` 1.12.0 cleared the critical advisory. The 10 November production dependency audit reported four moderate findings. Physical-device and push delivery verification remain open.
- Terraform defines an AWS environment. Live infrastructure and deployment remain unverified. The local proof of concept takes priority. [Infrastructure notes](../terraform/COST_REVIEW.md)

The original requirements, design, work breakdown and September evidence are available in the [prototype snapshot](https://github.com/haydenteh5526/DocVault/tree/6031e7242fcfcaa1b67b48ba2742c152113c9138/docs/archive/prototype).
